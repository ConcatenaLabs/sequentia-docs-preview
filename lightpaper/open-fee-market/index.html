The open fee market

Live on testnet Simplifies the whitepaper, Principle 2

Users can offer any asset issued on Sequentia as a transaction fee. Block producers decide which they accept.

The end of gas tokens explains why this matters. This page explains how it works, step by step.

Step 1: you offer a fee

When you send a payment, your wallet attaches a fee in an asset you hold. It can be the asset you are sending or a different one. The wallet shows the fee as an amount of that asset and its value in your currency.

No asset is the default. The staking token, SEQ, pays fees only where a producer has priced it, on the same terms as anything else, and a wallet must be told which asset pays a fee rather than assume one.

Step 2: nodes decide whether to pass it on

Your transaction first reaches a node, which decides whether to keep it and relay it to its peers. Each node has a price list: one rate per asset it knows. If the fee asset is on the list and the fee is high enough, the transaction is relayed. If the asset is not on the list, it is not.

This is why a wallet first asks its own node which assets it accepts, and offers only those.

Step 3: a producer decides whether to include it

A block has limited room. The producer building it wants the transactions that pay most.

To compare a fee in a stablecoin with a fee in tokenised gold, the producer converts each to a common scale: the amount offered multiplied by the asset’s rate on its price list. It then ranks transactions by value for the space they take, exactly as a Bitcoin miner ranks them by satoshis per virtual byte.

Whitepaper 2.2The common scale is not a coin

The scale is an abstract unit of account. It is a unit of measure and not an asset: nobody issues it, nobody can hold it, and no issued asset is ever defined to be it. Its purpose is to keep the comparison symmetric between assets.

A node’s thresholds (the minimum fee it will relay, the minimum it will include in a block, the increment a replacement must add) are each a single figure, and a fee can be measured against them only once it has been reduced to a single figure too. What the unit is worth is fixed by the price list: the rates state how many units one unit of each asset is worth.

Step 4: every node accepts the block

Once your transaction is in a block, every node accepts it, including nodes that would never have relayed it. Consensus checks only that the fee a transaction declares was really paid. It never asks what the fee was worth.

So there are three layers, and only the first is a rule of the network.

Layer Decides Can differ between nodes?
Consensus Whether a block is valid: was the declared fee really paid? No
Node policy Whether a node relays a waiting transaction Yes
Producer policy Which waiting transactions go into a block Yes

Refusing an asset is never a veto over the network. What a short price list costs is reach: a transaction travels from node to node, and may not arrive at the producer that would have included it if the nodes in between did not carry it.

If your fee is not accepted

Replace it. A waiting transaction can be replaced with one offering more, or the same value in a different asset. A wallet in user mode does this by itself for a transaction that has waited too long.

Go deeperRefusing an asset explicitly

An asset a producer has not priced has no value on that producer’s scale, so in practice it is not carried. A producer that wants to record a refusal explicitly may list an asset at a rate of zero, which is distinguishable from never having configured it at all.

Where the price list comes from

An operator may write it by hand. A node that prices the few assets its operator understands and ignores the rest is a fully working node, and the desktop wallet lets its user do this from a dialog.

Most will connect the node to a price server: a separate program that queries the market data sources its operator chose, applies that operator’s admission rules, and publishes a list the node reads.

Typical admission rules:

  • a minimum market capitalisation;
  • a minimum daily trading volume;
  • a maximum volatility;
  • a discount for illiquid assets.

On the testnet a node reads the network’s public price server by default, so it works with no configuration. On mainnet a node starts with an empty list until its operator writes one or connects to a server.

Whitepaper 2.4Why the price server is a separate program

It is kept outside the node deliberately: it issues third-party HTTP requests, holds API keys and parses JSON, none of which belongs in the process that validates blocks.

Operator documentation, including how to run your own: 05-operating-sequentia.md, section 3.

How producers are paid, and why they wait

Fees go to the producer through the block’s coinbase, and a coinbase cannot be spent for 1,000 blocks: about sixteen hours and forty minutes, the same in clock time as Bitcoin’s 100 blocks.

The wait does two jobs. It is a safety margin, because until it passes the block could still be undone by a Bitcoin reorganisation of its anchor. And it is an incentive: a producer must hold each fee asset for the whole period and bears its price risk. An illiquid or volatile asset may be worth less by then, so a user paying in one may need to offer more.

The market sets the price of that risk. No rule does.

What this replaces

Chains designed for tokens generally follow one of two models, and both have the same shape of problem.

  • A mandatory coin (Ethereum, Tron, BNB Chain, Solana, Algorand). Users must hold it in addition to what they actually want to transact, and make extra transactions just to acquire it.
  • A pegged bitcoin (Rootstock, Liquid). The whole chain then depends on the security of the peg, in the hands of a federation or a single entity.

Sequentia needs neither.
