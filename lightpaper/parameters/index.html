Parameters at a glance

Live on testnet For developers Simplifies the whitepaper, section v

Every figure used across the lightpaper, in one place. They are the values of the public testnet and the values fixed for mainnet, as stated in the whitepaper’s revised edition.

Consensus rule means every node enforces it and a block that breaks it is invalid. Node setting means each node applies it to its own behaviour; all nodes use the same default, and a different value changes speed, never validity.

Block subsidy None. Producers are paid in fees only Consensus Staking

Maximum number of stakers 10,000 (follows from the minimum) Consequence Staking

Unbonding Two steps: stake, then an unbonding output with no weight, spendable after 2,016 Bitcoin blocks (about 2 weeks) Consensus Checkpoints
Fee payable from an unbonding stake Up to 1% of the staking outputs spent Consensus Checkpoints
Payout notice 1,440 blocks (about 1 day) Consensus Staking
Payout epoch (split scheme) 1,440 blocks; paid in groups of about 32 delegators Consensus Staking

Election and committee

Parameter Value Kind Explained in
Leader election Proportional to stake, over a private verifiable random function Consensus Staking
Election seed The parent block’s Bitcoin anchor, plus the height Consensus Anchoring
Committee Public; min(registered stakers, 250) seats, apportioned by stake Consensus Finality
Quorum Strict majority of seats, plus one when odd: 126 of 250, 21 of 40, 1 of 1 Consensus Finality
Certificate About 300 bytes: the leader’s signature, one 96-byte aggregated BLS signature, one bit per member, and the signers’ seat total Consensus Finality
Fork choice at equal height Fully certified first, then the lower lottery output of the leader, then the lower block hash Consensus Never stuck

Parameter Value Kind Explained in
Minimum block spacing 60 seconds Consensus Lean blocks
Slot unit 10 seconds per rank Consensus Lean blocks
Block weight 400,000 weight units (a tenth of Bitcoin’s) Consensus Lean blocks
Timestamp ahead of the validating node At most 2 hours Consensus, judged against each node’s clock Lean blocks
Coinbase maturity 1,000 blocks (equal in time to Bitcoin’s 100) Consensus Fee market

Finality and liveness

Parameter Value Kind Explained in
Time to finality About 10 seconds after the block is proposed (about 7 to certify, plus 3 of observation) Result Finality
Collection window 500 ms + 25 ms per member: 6.75 s at 250 Node setting Finality
Round 700 ms + 35 ms per member: 9.45 s at 250 Node setting Finality
Rounds per collection Normally one; at most one per member Node setting Finality
Finality observation window 3 seconds; up to 30 seconds more while a competing certificate’s block is awaited Node setting Never stuck
Escaping stall The anchor advances by 3 Bitcoin heights, and at least one Bitcoin block interval (10 minutes, by median time) has elapsed Consensus Never stuck
Finality reconciliation A rival certificate at least 3 blocks higher, after 10 minutes without a certified extension Node setting Never stuck
Proposal stamped ahead Backed up to 150 seconds ahead of the member’s clock Node setting Finality
Clock agreement Within 60 seconds of the median of at least 5 peers Node setting Finality

Where they are set

On the testnet and on mainnet, consensus parameters are fixed in the node’s source code (src/chainparams.cpp) and are not read from the configuration file. A node given a flag that would change one refuses to start.
